# VERT Desktop Mac 增强版升级方案

目标：在现有 VERT 的本地转换基础上，补齐接近飞鼠格式的文档、PDF 与 OCR 工作流。参考功能，不复制飞鼠品牌或素材。

## 已确认的基础

本机应用为 VERT Desktop 1.0.0，Apple Silicon 架构，Tauri 应用，包含 FFmpeg、ImageMagick、Pandoc 可执行文件。公开上游提供 Rust/Tauri/React 源码。尚未验证本机各转换引擎的运行依赖。当前未在常见路径发现 Rust、LibreOffice、Tesseract 和 Poppler，实施时需要检查并安装必要组件。

## 方案比较

1. 推荐：从 VERT 源码扩展，沿用现有界面与图片、音视频转换能力，逐项新增文档工具。可维护，但需要构建 Rust 应用及适配 Mac 引擎。
2. 将飞鼠源码适配到 Mac：已有较丰富业务逻辑，但其最新公开完整版主要面向 Windows，原生引擎和高级 PDF 处理不能直接视为 Mac 可用，需要更大适配范围。

## 推荐的首轮范围

- Office：接入 LibreOffice，增加 DOC/DOCX、XLS/XLSX、PPT/PPTX 与 PDF 的可行转换路线；每种源文件只展示引擎实际支持的目标。WPS/ET/DPS 作为兼容性验证项，通过样本后才标记支持。
- PDF：合并、按页拆分、图片合并 PDF、PDF 导出图片及文字提取；支持页序调整。
- OCR：图片和扫描 PDF 提取中文、英文文字；扫描 PDF 逐页处理，明确区分文字提取和版式恢复。
- 保留并验证现有图片、音视频、Markdown 和 EPUB 转换。
- 批量任务：逐文件结果、失败原因、输出目录、打开结果位置和取消操作；有可靠总量时显示进度，否则显示阶段状态。

## 后续单独实现的范围

PDF 转可编辑 Word、复杂表格 PDF 转 Excel、复杂 WPS 文件及扫描版式恢复。它们需要独立样本和质量检查，首轮不承诺与原文档排版一致。

## 实现结构

保留现有 React 界面与 Tauri 命令结构，增加 Office、PDF、OCR 三类后端适配器。能力探测决定可用操作；引擎缺失时在对应功能说明具体缺少的组件。进程参数按独立参数传递，输出先写任务临时目录，成功后保存到用户选择的位置。源文件只读，避免输出文件名冲突覆盖。

转换期间保留任务标识与引擎进程，取消任务时停止对应进程并清理任务临时文件。失败保留简明原因，批量任务继续处理其他文件。OCR 默认中文与英文，模型在本地运行。

## 交付与验证

先构建一个可并行运行的增强版 .app，保留现有 /Applications/VERT Desktop.app。交付源码、构建说明和能力清单。通过真实小样本验证图片、音频、视频、文档、Office、PDF 和 OCR；检查中文文件名、空格路径、重复文件名、失败文件、批量与取消。只有实际通过的路线才记入已支持清单。完成后再确定是否替换原应用。
