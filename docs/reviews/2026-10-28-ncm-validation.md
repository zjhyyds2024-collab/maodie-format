# VERT Enhanced 1.6.1：网易云 NCM 支持与验收

日期：2026-10-28。用户确认歌曲为 .ncm，并说明桌面和下载文件夹各有一种格式。本地检查确认桌面是 NCM 音频，下载文件夹同名 LRC 是时间轴歌词，不包含音频。原件均保留。

## 实现

NCM 在前后端均识别为仅输入的音频格式。默认“还原原始音频”保留内部 MP3/FLAC/M4A 编码，以 FFmpeg stream copy 输出，不重新编码；实际文件后缀由内部音频决定。另选 MP3、FLAC、WAV、Opus 等输出时进入现有音频转码流程，既有预设和显式采样率仍适用。

增加独立的本地 NCM 读取模块，使用已安装的 cryptography AES 实现，不新增下载组件，不请求网络封面。格式结构参考 [ncmdump 实现](https://github.com/taurusxin/ncmdump/blob/master/src/ncmcrypt.cpp)，代码按本应用的请求接口与有界读取方式实现。检查文件头、AES 数据长度、填充、密钥前缀、元数据与封面块边界；正确跳过新版本无封面时的保留空间。按块处理音频，支持取消；临时解包目录随任务释放，原始 NCM 不改写。

保留元数据时写入可读取的标题、歌手、专辑，元数据损坏时提示但继续处理可读音频。独立封面暂不导出，不承诺完整保留全部特殊标签。选择关闭元数据时明确使用 -map_metadata -1。此功能仅涵盖已验证 NCM，不承诺其他平台的 QMC/KGM 等格式。

## 验证

- 5 项 NCM Python 专项：跨 1 MiB 块边界、带填充封面区、中文标签及转义、坏元数据降级、伪造/截断/超长头、不可覆盖源文件。全部 Python 测试共 33 项通过。
- 前端单元 180 项、E2E 24 项通过，包含大写 .NCM 识别、默认原始还原、NCM 不作为输出及转码请求。生产构建、ESLint 通过。
- Rust 常规 9 项通过；新增实际引擎集成测试通过：自行生成 MP3/FLAC，再构造 NCM，还原后的 PCM SHA-256 与原始音频一致，中文标签保留，NCM 原件字节一致。
- 15 项生产函数调用：13 项正常转换成功，2 项错误头/截断输入按预期拒绝。合成 MP3、FLAC、M4A 各测还原、转 WAV、关闭标签；真实用户 NCM 测还原、MP3、FLAC、Opus。正常产物均实际解码，标签开关及还原前后 PCM 检查通过。
- 真实文件内部为 MP3，44100 Hz，时长约 181.85 秒。还原前后的解码音频 SHA-256 一致，标题/歌手/专辑标签存在；源 NCM SHA-256 未变化。
